El problema

Un proceso manual expuesto a errores y reprocesos

Actualmente las novedades se consolidan mediante una planilla Excel. La manipulación repetitiva de celdas dificulta la validación, el seguimiento de cambios y la preparación uniforme de la información para contabilidad.

01

Registro disperso

La información se distribuye entre hojas, filas y columnas que deben revisarse manualmente.

02

Validación limitada

Un dato incompleto o escrito en un formato incorrecto puede afectar el consolidado mensual.

03

Poca trazabilidad

Resulta difícil identificar quién registró, modificó o validó cada novedad.

La solución propuesta

Una aplicación diseñada alrededor del proceso real

El sistema centraliza colaboradores, contratos, períodos y novedades, aplicando reglas de negocio antes de preparar los datos para contabilidad.

Colaboradores

Administración estructurada de datos laborales, bancarios y previsionales.

Períodos mensuales

Separación de la información por sucursal, año, mes y estado del proceso.

Novedades

Registro de horas extras, inasistencias, licencias, bonos, descuentos y anticipos.

Validaciones

Reglas para fechas, montos, cantidades, estados y campos obligatorios.

Trazabilidad

Identificación del usuario que registra, valida o genera una exportación.

Exportaciones

Preparación de archivos CSV o Excel para entregar información organizada.

Proceso propuesto

Tres etapas para controlar cada período

ETAPA 1

Captura

El usuario selecciona el período y registra las novedades correspondientes a cada colaborador.

ETAPA 2

Validación

El sistema comprueba reglas de integridad y un usuario autorizado revisa la información.

ETAPA 3

Exportación

Las novedades validadas se consolidan en un archivo destinado al proceso contable.

Alcance: la aplicación organiza las novedades y facilita su entrega. No reemplaza el cálculo legal ni el motor de liquidación de remuneraciones de Nubox.

Privacidad y seguridad

La información laboral requiere controles desde el diseño

El sistema está planteado para uso interno y restringe sus recursos a usuarios autenticados. Las credenciales y los datos reales nunca se almacenan en el repositorio público.

Autenticación obligatoria

Los endpoints de la API requieren una sesión válida.

Integridad de los datos

PostgreSQL y Django aplican relaciones, restricciones y validadores.

Datos ficticios en demostraciones

Las pruebas y evidencias públicas no contienen información real de colaboradores.
